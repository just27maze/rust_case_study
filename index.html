01 — overview

What Is Rust?

A programming language for building reliable, efficient, and performance-critical software. It combines native-code performance with compile-time memory- and thread-safety checks, without requiring a garbage collector.

Source: The Rust Programming Language

02 — timeline

History

  1. 2006–2009

    Rust began as an early personal project by Graydon Hoare.

  2. 2009

    Mozilla began investing in Rust's development.

  3. 2015

    Rust 1.0, the first stable release, was released.

  4. 2015–present

    Rust has continued to develop through regular releases, an expanding ecosystem, and community-supported infrastructure.

  5. 2025

    Rust marked ten years since the release of Rust 1.0.

Source: Rust Foundation — 10 Years of Stable Rust

03 — traits

Characteristics

01

High performance

Compiles to native machine code and has no runtime or garbage collector.

02

Memory safety

Ownership rules prevent many memory-related errors at compile time.

03

Thread safety

The type system helps prevent unsafe memory access across threads.

04

Predictable resource use

Memory can be released when it is no longer needed, avoiding garbage-collection pauses.

Modern tooling

Includes Cargo for building, dependency management, testing, and packaging; offers useful compiler error messages and documentation.

05 — case study

Discord Read States: Go to Rust

Case Study Title
Discord Read States: Removing Latency Spikes by Moving from Go to Rust
Programming Language
Rust
Organization / System
Discord / Read States service
Domain / Industry
Real-time communication, distributed systems, and performance-critical backend services
Source Consulted
Discord Engineering — Why Discord is switching from Go to Rust; The Rust Programming Language

Discord's Read States service records which channels and messages a user has read. Because the service is accessed whenever users connect, send messages, and read messages, it is part of Discord's performance-critical path. Discord migrated the service from Go to Rust after recurring latency spikes affected responsiveness.

Source: Discord Engineering

06 — glossary

Key Terms

Discord is a communication platform whose backend systems must respond quickly to user connections, messages, and read activity. In this case, Discord is the organization that migrated its Read States service from Go to Rust.

The Read States service keeps track of the channels and messages each user has read. It is accessed when a user connects to Discord, sends a message, or reads a message.

Rust is a systems programming language designed for reliable and efficient software. Its ownership model and type system enforce memory and thread safety at compile time without using a garbage collector.

Go is the language originally used for Discord's Read States service. In this case, its garbage collector periodically scanned the large cache, contributing to CPU and latency spikes.

LRU means Least Recently Used. It is a cache strategy that removes the least recently accessed entries when space is needed for newer entries.

A cache is fast, temporary storage that keeps frequently needed data readily available. A cache miss occurs when requested data is not in the cache and must be retrieved from a slower source, such as a database.

Garbage collection is an automatic memory-management process that identifies and frees memory that is no longer in use. In Discord's Go service, garbage collection had to scan the large LRU cache, causing periodic performance overhead.

A latency spike is a sudden increase in the time required for a system to respond. Discord experienced large periodic latency spikes that negatively affected user experience.

A HashMap is a data structure that stores key-value pairs and uses hashing to locate values efficiently. Discord initially used a HashMap in its LRU cache implementation.

A BTreeMap is a key-value data structure organized as a balanced tree. Discord changed from a HashMap to a BTreeMap in the Rust service to improve memory usage.

A canary deployment releases a new version to a small part of the system before a full rollout. Discord first deployed the Rust service to one canary node, fixed missing edge cases, and then deployed it across the full fleet.

Source for all terms: Discord Engineering; Rust definition also supported by The Rust Programming Language

07 — the problem

The Problem That Discord Was Having

  • The Read States service maintained an LRU cache containing tens of millions of Read States.
  • It processed hundreds of thousands of cache updates per second.
  • The Go implementation was fast most of the time, but it experienced major latency and CPU spikes roughly every two minutes.
  • Go's garbage collector scanned the large LRU cache to determine which memory could be freed.
  • Reducing cache capacity made garbage-collection spikes smaller, but it increased cache misses.
  • More cache misses caused additional database loads and increased 99th-percentile latency.

The result was a trade-off: a large cache caused heavier garbage-collection work, while a smaller cache caused more slow database accesses.

Source: Discord Engineering

08 — the solution

How Rust Helped

No garbage collector

Removed the periodic garbage-collection scans that caused latency spikes in the Go implementation.

Ownership model

Rust could determine when an evicted Read State was no longer needed and free it immediately.

Compile-time memory checks

Ownership and borrowing rules checked memory access during compilation.

Type system and generics

Helped remove duplicated code and some manual cross-goroutine memory-protection code.

Thread-safety support

Allowed the system to reason about memory safety across threads.

Efficient native performance

Supported improvements in latency, CPU use, and memory use for a highly concurrent network service.

Process Toward the Solution

  1. Discord selected Read States because it was a small, self-contained service suitable for a controlled rewrite.
  2. The team created an initial Rust version by roughly translating the Go implementation.
  3. They simplified the service using Rust's type system, generics, and memory model.
  4. Discord used nightly Rust because stable Rust at the time did not yet provide suitable asynchronous-programming support.
  5. The new service was load-tested and initially matched Go's normal latency without the periodic spikes.
  6. The team profiled and optimized the implementation — replacing HashMap with BTreeMap, swapping the metrics library, and reducing memory copies.
  7. The service was deployed to a single canary node, edge cases were fixed, then rolled out to the full fleet.
  8. Discord later increased cache capacity to eight million Read States per server without reintroducing GC pauses.

Source: Discord Engineering

09 — strengths

Strengths of Rust

Memory & thread safety

Rust's ownership model and type system prevent many classes of bugs at compile time.

No garbage-collection pauses

Rust can be especially valuable for services where predictable latency matters.

High performance

Rust compiles to native code and can support low-resource, performance-critical applications.

Productive tools

Rust provides Cargo, documentation, compiler guidance, formatting tools, and editor support.

Strong refactoring support

Type safety and the borrow checker can make code changes safer as requirements evolve.

Broad use cases

Rust can be used for network services, embedded devices, command-line tools, WebAssembly, and backend services.

Growing ecosystem

Rust has long-term investment from contributors, institutions, community tools, and the Rust Foundation.

Sources: The Rust Programming Language; Bitfield Consulting; Rust Foundation; Discord Engineering

10 — weaknesses

Weaknesses of Rust

Steep learning curve

Developers must learn ownership, borrowing, lifetimes, and related concepts.

Adoption cost

Teams may require considerable training and adjustment before they become productive in Rust.

Library & ecosystem gaps

Some application areas may have less mature library support than established languages.

Hiring concerns

Organizations may find it challenging to recruit experienced Rust developers.

Migration complexity

Rewriting or integrating Rust into large legacy systems can be expensive and may not always justify the benefit.

Not ideal for every project

Tight deadlines, rapid prototypes, existing technology investments, and project requirements can make another language a better fit.

Ecosystem risk in the case

Discord used nightly Rust for async support at the time, accepting instability and more difficult tooling before async support became available on stable Rust.

Sources: Fulton et al.; ForrestKnight; Discord Engineering

11 — closing

Summary

Discord moved its Read States service from Go to Rust to solve recurring latency spikes caused by garbage collection over a very large cache. Rust's lack of a garbage collector and its ownership-based memory management removed the source of those pauses. After profiling, data-structure changes, memory optimizations, load testing, and a canary rollout, Discord reported better latency, CPU use, and memory use than the previous Go implementation.

The case demonstrates that Rust can be a strong choice for performance-critical services with strict latency requirements. However, the improvement came not only from Rust itself but also from disciplined engineering practices: measurement, profiling, optimization, testing, and gradual deployment. Rust should therefore be selected based on a project's actual performance, safety, ecosystem, and organizational requirements.
